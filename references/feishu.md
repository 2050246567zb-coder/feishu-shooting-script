# 飞书执行与验收

## 默认脚本行为

`scripts/feishu_shots.py publish` 接受经过 Codex 阅读原文后整理的 JSON。默认新建一个 Base；指定 `--template-base-token` 则复制该用户模板的结构。只往本次新创建或任务状态文件已绑定的副本写入，不接受任意已有 Base 作为覆盖目标。

七列类型和三个视图来自 `assets/template.json`。复制的模板需要有这七个兼容字段；有额外自定义字段时保留，不擅自删列。缺字段或类型不兼容时停在已创建的副本，向用户解释需要选择兼容模板或另建标准表，不自动转换字段类型。

CLI 总是使用用户身份。记录键使用实时 `field_id`，选项使用已经存在的名称数组，checkbox 使用布尔值。新建时把本次地点选项一并放入 schema；复制结构时只对空副本的地点字段作 read-modify-write，先 dry-run，再保留原配置增加选项。附件通过 `+record-upload-attachment` 上传，不能作为普通 CellValue 写入。

在 Windows 上脚本会解析 npm 的 CLI shim，直接用 Node 调用已安装的 `@larksuite/cli/scripts/run.js`，避免把脚本原文拼进 cmd/PowerShell 命令。无法安全解析 shim 时停止并要求指定真实 CLI 可执行入口，不使用 `shell=True`。

## 中断与重跑

- 本次任务目录中的 `state.json` 绑定了计划指纹、目标 Base 与表。恢复时复用同一份 JSON、同一目录。
- 创建前记录 pending。若创建请求结果不明且尚未拿到 Base Token，不自动再次创建；先检查用户云空间中是否已经生成本次表，确认后补回状态或说明阻塞点。
- 写记录前读回现有镜号。已存在且口播、描述一致的行跳过，保留其参考图、地点、备注和拍摄勾选；相同镜号对应不同正文或出现重复镜号时停止，不覆盖团队修改。
- 每批最多200行，串行写入。失败时先核对是否已经写入，不能因为报错就整批重投。未确认写入的部分保留任务状态，等待同一任务续传。
- 配置写入是幂等操作，遇明确短时限流可以短暂等待后仅重试一次；认证、权限、表不存在、字段类型等错误不循环重试。
- 每个附件都有上传前状态。结果不明时根据该行的新附件 token、文件名与大小恢复；无法唯一确认就停止，避免重复附图。

## 线上核对

记录统一导出成任务目录里的 NDJSON 再比较，不能把 API 的“请求成功”当作原文完整性证明。核对全部本次镜号、数量、顺序、口播和画面描述；新写入的行还要核对地点、备注和未拍状态。恢复时已有行的现场补充不能用源 JSON 强行覆盖。

视图初始化后检查列顺序、分组和待拍筛选；同一份底层记录不复制到三个独立表。原文核对由 Codex 负责，脚本读回校验只证明线上数据与整理后的 JSON 相符。

## 列宽与页面

目前随包 CLI 适配不设置列宽。用户已有调好的模板时，复制其结构可以优先保留布局，但仍以实际页面为准。新建表需要时通过可用浏览器界面调整镜号列，目标约120px，其他列保留足够阅读空间。

先看当前截图再选列边界，调整一个视图后检查实际效果，再处理下一个视图。不要复制作者机器的像素坐标；不要用隐藏应用状态、未公开接口或伪造 schema 属性改列宽。遇自动安全检查或用户中断，停止 UI 操作并清楚说明原因。数据已经完成时不因此重复建表或删数据。

## 原地修改

只有用户明确要求修改现有表时才使用常规飞书工具原地调整。先读当前字段、视图和必要记录，只改指定项目。删除字段会影响该列内容，目标明确且用户已经要求删除时无需重复征求相同许可；不因 Skill 默认七列就自动删除用户自己的其他列。不把这次用户对某张表的修改授权泛化成以后所有表的清理许可。
